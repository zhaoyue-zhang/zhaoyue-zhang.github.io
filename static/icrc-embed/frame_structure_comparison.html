关键观察

  1. UEC & SUE 思路一致 它们的端到端 CRC 都跳过 L2 头 — 路径上有 in-network 操作 (ECN 标记 / packet trimming / LLR / ECN→PFC 映射), MAC 字段可能被改, CRC 不能因此失效。这是端到端校验的标准做法 (IPsec AH 也跳过 L2)。
  2. ETHLINK 反其道 ICRC 从 OEFH 首字节起算, 路径上 不能改 datalink header (包括 reserved/entropy/GPU-ID), 假设网络是端到端透明的专用 fabric, 不走标准以太网交换机 (否则 802.1Q VLAN 标记、LLR 等动作会破坏 ICRC)。
  3. SUE Lite 是个极端特例 直接砍掉 R-CRC, 仅靠 L2 FCS + 路径 LLR + 无损 PFC/CBFC 兜底, 适合"短距、超低延迟、可以信任物理链路"的场景 (典型如机柜内 Scale-Up)。
  4. ETHLINK 的 tie1 创新 把 TTL/DSCP/ECN 等可变字段在 ICRC 计算时置 1, 接收端也置 1 再算, 让端到端校验能容忍路径上对这些字段的修改 — 类似 IPSec AH 的做法, 但 ETHLINK 把"可变字段"的精确集合明确列在了 spec 里。
  5. datalink/Txn reserved 按原值 这条对协议设计是双刃剑: 路径上 reserved 字段不能被改 (否则 ICRC 失效), 但换来了 OEFH 头未来扩展时不需要重新设计 ICRC 算法, 字段加进 reserved 区后接收端按 spec 保留原值即可。
